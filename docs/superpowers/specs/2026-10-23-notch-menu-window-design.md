# 刘海屏菜单入口替代窗口设计

## 目标

在刘海遮挡系统菜单栏的 macOS 屏幕上提供可靠的股票监控入口，同时保留普通屏幕上原有的系统菜单栏体验。该改造只替换菜单入口和旧浮动窗口，不改变行情刷新、提醒、通知、盘中确认、交易守卫或数据持久化逻辑。

## 交互

1. 系统菜单栏入口继续保留。普通屏幕点击后展示现有完整菜单树。
2. 启动和屏幕配置变化时检测菜单栏可用区域。刘海安全区明显大于系统菜单栏厚度时，判定主屏菜单栏入口存在遮挡风险。
3. 判定存在遮挡风险时，在屏幕右上方安全区域显示替代窗口；普通屏幕不显示该窗口。
4. 窗口显示当前行情摘要。点击窗口或“菜单”区域时弹出原生下拉菜单，支持现有二级、三级菜单；点击菜单外部自动收起。
5. 窗口可拖动，按显示器配置保存位置。位置越界或配置丢失时回到右上角安全区域。
6. 浏览器全屏、全屏应用和所有桌面空间中，替代窗口保持可见且不抢占当前应用焦点。
7. 替代窗口没有独立关闭按钮。退出仍通过菜单中的“退出”；异常时系统菜单栏入口继续作为兜底。

## 架构

### MenuBarFallbackWindow

新增独立 UI 组件，负责：

- 创建悬浮 `NSPanel`，启用全屏辅助窗口、跨桌面空间和不抢占焦点行为。
- 显示单行/双行行情摘要和菜单点击区域。
- 在点击时使用当前 `StockMenuBar.menu` 菜单树构建 `NSMenu`，弹出后不缓存动态子菜单。
- 接收菜单项选择并转交原 `rumps` 回调。
- 保存、恢复和修正窗口位置。

组件不读取行情、不启动定时器、不生成信号，也不调用交易动作。

### 屏幕适配器

新增纯函数/适配层，输入屏幕安全区、菜单栏厚度和屏幕边界，输出是否显示替代窗口、默认窗口位置和修正后位置。无法读取安全区或检测结果不确定时，显示替代窗口。

### StockMenuBar 集成

- 移除 `FloatingWindow`、浮动窗口菜单项、浮动模式状态和旧菜单数据投影。
- 将原来的行情摘要更新改为只更新 `MenuBarFallbackWindow`。
- 初始化完成后评估屏幕条件；普通屏隐藏窗口，刘海风险屏显示窗口。
- `NSScreen` 参数变化时重新评估。后台刷新线程继续运行，窗口只接收主线程 UI 更新。

## 菜单复用

- 现有 `self.menu` 是唯一菜单来源，避免系统菜单栏和替代窗口出现功能差异。
- 菜单树在每次点击时读取，动态涨跌榜、涨跌停、观察池、持仓、设置和今日要闻使用最新内容。
- 菜单项标题、启用状态、嵌套层级和 callback 与原菜单一致。
- 分隔线和只读说明项保持原样；回调不得被窗口层重写。

## 数据与状态

- 仅持久化窗口坐标，不持久化菜单快照或行情内容。
- 坐标文件位于现有日志目录，使用 JSON 原子写入；损坏文件按无保存位置处理。
- 窗口摘要使用现有刷新周期的菜单投影数据，不新增轮询、网络请求或后台线程。

## 异常处理

- PyObjC/AppKit 不可用：应用继续使用系统菜单栏，不启动替代窗口。
- 安全区读取失败或结果不确定：显示替代窗口，避免入口不可达。
- 菜单构建或回调转发失败：记录日志并显示“菜单暂不可用”，不终止刷新和通知。
- 外接屏插拔、分辨率缩放、显示器重排：重新计算可见性并把窗口夹回目标屏幕安全区域。
- 窗口创建失败：继续运行系统菜单栏入口，不影响其他功能。

## 移除范围

- 旧 `FloatingWindow`、紧凑/菜单双模式、手动表格导航和浮动窗口显隐开关。
- 旧浮动窗口相关初始化、更新、关闭回调和菜单标题同步。
- 对应旧组件测试，替换为替代窗口行为测试。

## 测试

1. 屏幕适配纯函数：普通屏、刘海屏、缺失安全区、异常数值和多显示器选择。
2. 菜单树适配：一级/二级/三级菜单、分隔线、callback 转发和动态菜单刷新。
3. 窗口位置：默认右上安全区、保存/读取、越界修正和屏幕变化。
4. UI 层级：悬浮、跨桌面、浏览器全屏辅助和不抢占焦点配置。
5. 集成：窗口点击不阻塞刷新线程；旧浮动窗口入口不存在；系统菜单栏菜单仍可用。
6. 回归：全量测试、Python 编译、盘中动作守卫测试和 `git diff --check`。

## 验收标准

1. 普通屏仍可从系统菜单栏使用完整功能。
2. 刘海风险屏启动后右上角安全区域出现替代窗口，无需点击不可见菜单项。
3. 点击替代窗口能看到并操作原有完整菜单树。
4. 浏览器普通窗口和全屏状态下均能看到替代窗口。
5. 新窗口显示、收起、拖动或菜单操作不影响后台盘中刷新、提醒和通知。
6. 旧浮动窗口不再启动、不再出现在菜单，也没有残留入口。
7. 窗口创建、屏幕检测或菜单构建失败时，系统菜单栏入口和后台监控保持可用。
8. 新增行为由自动化测试覆盖，原有测试继续通过。
