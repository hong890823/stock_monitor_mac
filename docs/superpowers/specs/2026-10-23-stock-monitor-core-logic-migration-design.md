# Stock Monitor 核心逻辑迁移设计

## 目标

把 `/Users/stephen/Documents/mi/privacy/stock-monitor-android/docs/stock-monitor-core-logic-summary-2026-10-23.md` 中的“数据采集 → 数据校验 → 风险过滤 → 观察晋级 → 展示/提醒”规则迁移到 `stock_monitor_mac`。本轮全量对齐该文档第 13 节操作清单，不改变已有盘中买卖、做T和A股T+1守卫的执行语义。

迁移后，UI只消费结构化结果。数据缺失时显示“暂缺/样本不足”，不补造数值，不以缺失数据阻断个股晋级，也不把观察晋级解释为自动下单。

## 范围

本次覆盖：

1. 今日要闻的抓取渠道、发布来源、分类、排序和链接保留。
2. 东财涨跌停池、新浪近似扫描兜底、封板质量准入和涨停/跌停排序。
3. 单日与多日资金流规则。
4. 候选池三条策略、状态机、定时确认和淘汰规则。
5. 市场/板块晋级负向过滤器的可恢复开关。
6. 持仓、自选股、选股列表、观察池和涨停/跌停列表的结构化展示。
7. JSON兼容迁移、回归测试和历史样本回测指标。

本轮不实现自动交易、订单提交、真实资金账户操作，也不调整现有盘中信号冷却和通知去重策略。

## 总体架构

### 分层

- **采集层**：负责东财/新浪接口、字段标准化、来源时间、抓取渠道、原始发布来源和数据新鲜度。
- **校验层**：统一校验交易日期、来源、有限数值、非负成交量/成交额、价格一致性和缺失值。校验结果分为`VALID`、`LOW_CONFIDENCE`、`UNKNOWN`、`INVALID`。
- **策略层**：新增纯函数策略模块，不访问网络、文件、菜单或通知。输入标准化数据，输出结构化证据和决策原因。
- **状态层**：`ObservationPool`负责候选状态机、确认轮次、历史快照、淘汰和原子持久化。
- **编排层**：`StockMenuBar`现有刷新入口负责取数、调度、调用策略层、写观察池、生成报告和触发提醒。
- **展示层**：`observation_ui.py`及菜单/浮窗只读取结构化结果，负责分组、排序、分页、展开/收起和文案。

### 新增纯策略模块

- `limit_up_policy.py`：东财涨停池准入、封板质量分、涨停/跌停排序和新浪兜底标记。
- `capital_flow_policy.py`：单日、近3日、近5日资金流分类、置信度和评分影响。
- `candidate_state_policy.py`：候选状态迁移、确认轮数、时间窗口、重新封板清零和淘汰判定。
- `promotion_environment_policy.py`：指数跌幅、跌停广度、关联板块同步转弱的晋级过滤判定及开关。
- `news_digest_policy.py`：新闻分类、优先级、排序、截断和来源展示模型。

现有 `capital_flow.py` 保留网络取数和缓存职责，将策略计算委托给 `capital_flow_policy.py`；`limit_seal_events.py` 继续负责盘中封板事件，不承担日频涨停池准入。

## 数据模型

### 标准化数据

每个数据对象必须包含：

- `code`、`name`、`as_of`、`trade_date`。
- `fetch_channel`：实际抓取渠道，如`EastMoney`或`Sina`。
- `publisher_source`：新闻原始发布媒体；行情类数据可为空。
- `quality`和`missing_fields`。
- 可序列化的证据列表，每项包含规则、观察值、阈值和结论。

资金流名称使用“主力净流向/主动买卖净流向”，不得写成“已确认机构资金”。资金流金额统一格式化为万元或亿元，比例明确为主动买卖净流向占成交额比例。

### 观察池版本3

观察池JSON从`version=2`迁移为`version=3`，保留`records`映射，并在记录中增加：

- `strategy`：`PRE_BREAKOUT`、`LEADER`或`LIMIT_UP_CONTINUATION`。
- `state`：`OBSERVING`、`NEAR_ENTRY`、`BUY_CANDIDATE`或`ELIMINATED`。
- `entry_destination`：统一写为`PRE_BREAKOUT / 启动前潜力`、`LEADER / 强势龙头`或`LIMIT_UP_CONTINUATION / 涨停持续观察`。
- `confirmation_rounds`、`last_confirmation_at`、`confirmation_started_at`。
- `limit_streak`、`open_count`、`seal_quality_score`、`data_coverage`、`related_sectors`。
- `flow_window`：最近5个交易日的有效资金流快照及置信度。
- `risk_evidence`、`breakout_risk`、`last_limit_seal_event`。
- `eliminated_reason`、`exit_date`、`reentry_cooldown_until`。

旧记录读取时保留已有阶段、评分、连续观察标记和历史；缺少字段时使用中性默认值，不猜测历史封板质量、板块归属或资金流。版本2记录只在读取时迁移，成功保存后写入版本3；保存失败不得覆盖旧文件。

## 核心规则

### 涨停池与封板质量

- `LimitCandidatePolicy`只接受东财涨跌停池的正式字段；新浪近似扫描仅作可用性兜底，不参与封板质量晋级。
- 普通涨停候选准入要求`limit_streak >= 1`、`open_count <= 1`，且`封单/流通市值 >= 0.5%`或`封单/成交额 >= 10%`。
- 合格候选进入`LIMIT_UP_CONTINUATION`；未合格涨停股进入`LEADER`观察轨，按涨幅最多保留前100只。
- 封板期间状态固定为`OBSERVING`，不进入普通买点，不发普通买入晋级，不因观察天数超时淘汰。
- 开板后清空封板期普通买点结论并重新评估；重新封板清零确认轮数。
- 涨停列表按封板质量综合分降序；跌停列表按跌幅升序，不套用涨停评分。

### 资金流

- 单日价格上涨且净流向`>= 3%`为`SUPPORTIVE`，最多加1分。
- 单日价格上涨且净流向`<= -3%`为`DIVERGENT`，暂缓普通买入确认。
- 单日价格下跌且净流向`<= -3%`为`RISK`，加强风险提示。
- 单日价格下跌且净流向`>= 3%`为`ABSORPTION_WATCH`，只作承接观察。
- 成交额小于500万元或字段缺失时为低置信度，不加减分。
- 最近3日平均净流向`>= 3%`且至少2日为正时为持续流入，加1分。
- 最近3日平均净流向`<= -3%`且正向日不超过1日时为持续流出，暂缓晋级。
- 样本不足3日为`ACCUMULATING`，不参与晋级评分；任一低成交额样本使窗口低置信度。
- 资金流只影响候选晋级和分析文案，不改变盘中买卖、做T或T+1提醒。

### 候选状态机

- 策略路由：快扫严格/宽松、趋势深扫和513结果统一映射到`PRE_BREAKOUT / 启动前潜力`；龙头承接走`LEADER`；合格涨停走`LIMIT_UP_CONTINUATION`。
- `PRE_BREAKOUT`和`LEADER`在普通门槛通过后进入`NEAR_ENTRY`，再按新行情样本复评。
- 普通候选需要2轮确认；`limit_streak >= 3`需要3轮确认。
- 相邻确认至少间隔15分钟，单轮确认从首次待确认起不超过45分钟；超时重置，不把旧样本当新样本。
- 确认必须使用时间分离的新行情样本和价格/趋势条件，累计成交量增长不得单独构成确认。
- 所有普通买入门槛、资金流持续流出、价格趋势破位、高位派发、缩量加速、突破失败和封板质量偏弱均优先于晋级。
- `BUY_CANDIDATE`只表示观察状态升级，不代表可执行买入；执行仍由现有`trade_action_guard.py`和T+1策略最终决定。
- 连续3个交易日走弱或观察10个交易日仍未确认时进入`ELIMINATED`。数据缺失、抓取失败和非交易日不计观察日、不推进确认。

### 市场/板块晋级过滤

- 保留三类阈值：主要指数跌幅达到0.8%、跌停数至少20且多于涨停数、已知关联板块全部`<= -1%`。
- 默认配置`promotion_environment_gate_enabled = false`，因此只记录环境证据，不返回晋级拦截。
- 开关启用时，上述任一明确负面条件可暂缓`NEAR_ENTRY → BUY_CANDIDATE`；未知市场、涨跌停或板块数据保持`UNKNOWN`，不强行拦截。
- 个股级风险继续生效，不受市场过滤开关影响。

## 展示与提醒

- 持仓和自选股支持单项展开/收起及一键全部展开/收起；收缩态只显示核心信息。
- 展开态显示代码、价格、评分、支撑/压力、量价、资金流、近3日资金流、入场结构、结构依据和失效/止损。
- 选股列表按评分/优先级降序排列，每页最多8条，并提供翻页入口。
- 涨停、跌停列表分别提供批量展开/收起，保持列表间距和各自排序。
- 选股卡片和详情均显示`入池去向`；观察池只突出`BUY_CANDIDATE`、`NEAR_ENTRY`和`LIMIT_UP_CONTINUATION`，纯观察、暂缓参与和已淘汰不混入主要入场列表。
- 三条策略分别显示“买点已确认/买点待确认”，不创建脱离策略的独立买点列表。
- 新闻按“宏观/政策 > 行业板块 > 公司事件 > 市场快讯”分类，再按发布时间排序；卡片最多5条，详情最多20条，链接保持可点击。
- 所有缺失、低置信度、兜底来源和未知状态都直接展示，不用猜测值替代。

## 错误处理

- 网络失败、响应字段异常、日期过期、非有限数值和结构损坏均进入`UNKNOWN`或`INVALID`，保留上一次有效持久化数据。
- 采集错误只影响对应数据域；行情缺失不等同于价格走弱，资金流缺失不等同于流出。
- JSON写入使用同目录临时文件、`fsync`和原子替换；失败保留旧文件并把错误暴露到日志/报告。
- 旧版本记录迁移失败时拒绝静默覆盖，报告兼容错误并继续使用内存中的安全空状态。
- UI渲染不得抛出因缺失字段导致的异常，缺失值统一显示`暂缺`或`样本不足`。

## 测试策略

纯策略模块使用固定日期和构造样本做单元测试，不依赖网络或系统时钟。重点覆盖：

1. 涨停准入的阈值边界、东财/新浪来源隔离、涨停/跌停排序。
2. 资金流单日四象限、3日窗口、5日保存、低成交额和样本不足。
3. 2轮/3轮确认、15分钟间隔、45分钟超时、累计成交量不确认、重新封板清零。
4. 三条策略路由、状态迁移、3日走弱、10日淘汰、缺失日期不计数。
5. 市场过滤开关关闭时只记录证据，开启时三种负向条件和未知数据行为。
6. 观察池版本2→3迁移、缺字段默认值、原子写失败和损坏JSON。
7. UI分组、每页8条、展开/收起、入池去向、资金流单位、新闻来源/链接。
8. 全部动作出口继续通过T+1守卫，`BUY_CANDIDATE`不产生自动下单承诺。

完成后运行`python3 -m unittest discover -s tests`，并对受影响模块执行`python3 -m py_compile`。再用历史样本计算候选晋级后的次日、3日、5日收益、最大回撤、胜率和错过率，作为阈值调优依据，不把回测结果直接写成收益保证。

## 实施顺序

1. 新增标准化数据模型、校验器、资金流/涨跌停/市场/新闻纯策略，并补齐单元测试。
2. 迁移观察池到版本3，接入状态机、确认计时、封板质量和JSON兼容。
3. 接入现有定时刷新、候选扫描、观察池报告和通知编排。
4. 更新持仓、自选股、选股、观察池、涨跌停和新闻展示。
5. 运行全量回归、离线构建、实盘模拟和历史样本回测，根据结果调整阈值。

## 验收标准

1. 文档第13节5项操作全部可由测试或界面行为验证。
2. 快扫严格/宽松、趋势深扫和513统一显示`PRE_BREAKOUT / 启动前潜力`。
3. 观察池按三条策略和状态分组，主要列表不混入纯观察、暂缓参与或淘汰记录。
4. 市场/板块晋级过滤默认关闭且可恢复；个股级风险仍正常生效。
5. 封板期间不产生普通买入晋级；开板后重新确认，重新封板清零确认轮次。
6. 资金流只作晋级辅助，不改变盘中动作和T+1规则。
7. 旧观察池记录可兼容读取，缺失字段不被猜测，保存失败不损坏旧状态。
8. 所有新增策略可独立单测，全量项目测试通过，最终文案不承诺自动下单或收益。
