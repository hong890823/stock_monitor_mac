**关键 join 规则**：利润表里有、现金流量表里没有的报告期**直接丢弃**——否则经营现金流会读成 0，把「利润含金量」整块毁掉。

**重试**：所有调用 `retries=2, delayMs=800`（唯一例外是 `latestValuationDate`，Android 没套 retry——移植时**补上**）。

**单位**：接口金额一律**元**，不换算；只在展示层用 `yi(v) = v/1e8` 显示「亿」。增长率与毛利率在单季对象上是**百分点**（×100），接口来的占比是**小数**。

## 1.2 三条单季差分硬规则（最容易移植错的地方）

财报接口给的是**年初至今累计**，必须差分成单季：

1. **只在同年相邻季度做差分**：`prevYear == year && prevMonth + 3 == month` 才相减。
   跨年**不分**——`2025Q1 − 2024年报` 会把整个 2024 年加进 Q1。Q1 本身就是单季，直接用累计值。
2. **中间缺期就不差分**：那一个「季度」会静默持有多个季度的累计值（明知不完美但不会灾难性错误）。
3. **TTM 要先对全序列差分，再取最后 4 个单季求和**。
   如果只对最后 4 个累计值差分，会把三季报当成一个单季，TTM 严重虚高。不足 4 期时 TTM 就是已有单季之和（**不年化**）。

单季标签：`YY + Q + 季度`，`03→Q1 / 06→Q2 / 09→Q3 / 其它→Q4`（如 `25Q2`）。保留最近 **8** 个单季（4 个同比点需要 8 个单季）。

单季衍生值：
- `毛利率 = (营收 − 成本) / 营收 × 100`（营收为 0 给 null）
- `营收同比 = (本期/去年同期 − 1) × 100`，要求去年同期营收 > 0
- `净利同比` 同上，但**要求两期净利都 > 0**——亏转盈/盈转亏给 null（不硬算）

## 1.3 指标体系

### 估值
| 指标 | 公式 | 说明 |
| --- | --- | --- |
| PE-TTM / PB-MRQ | **直接取接口值** | 不自己算 |
| PE 历史分位 | 历史序列 `filter(>0)`，需 **≥20 个交易日**，`count(≤当前)/n × 100` | 0~100 |
| PB 历史分位 | 同上 | |
| EPS | `TTM归母净利 / 总股本` | 元，TTM 归母口径（非静态非动态） |
| BPS | `归母净资产 / 总股本` | 元 |
| 扣非 PE（仅提示） | `扣非占比 < 0.80` 时提示：扣非 EPS≤0 说「扣非后是亏损的」，否则给「PE 从 X 倍变成 Y 倍，扣非口径下更贵」 | |
| 总市值 | 同业页里自己的 `TOTAL_MARKET_CAP` | **没有流通市值** |
| PS / PEG / 股息率 | **代码里不存在** | 不要自己发明 |

### 盈利（全 TTM）
- `毛利率 = (TTM营收 − TTM成本) / TTM营收`
- `净利率 = TTM归母净利 / TTM营收`
- `ROE = TTM归母净利 / 期末归母净资产` —— **期末近似，不是加权/摊薄/平均**；净资产≤0 给 null
- **没有** ROA / ROIC / 加权 ROE

### 成长
- 单季营收同比 / 净利同比序列（见 1.2）
- **趋势判定用「最近 4 个非空同比的中位数」**，不是「连续 N 季增长」的计数
- **没有环比、没有扣非同比**
- 两条时点提示：
  - 最近两季净利同比都 < 0 → 「历史估值分位看着便宜可能是陷阱」；只有最新 < 0 → 「参考价值要打折」
  - `PE分位 ≤30 且 近4季净利同比中位 ≥50` → 「低 PE 可能是盈利高点撑出来的，先确认是不是周期股」
  - `PE分位 ≥80` → 「当前 PE 处于历史 X% 分位，估值本身不便宜」

### 质量 / 安全
| 指标 | 公式 |
| --- | --- |
| 扣非占比 | `TTM扣非 / TTM归母` |
| **利润含金量** | `TTM经营现金流 / TTM归母净利` |
| **收现比** | `TTM销售收现 / TTM营收`（含税口径正常 1.0~1.13；票据结算多的制造业天然 <1） |
| 有息负债 | `短借 + 长借 + 应付债券 + 租赁负债` |
| 净现金 | `货币资金 − 有息负债`（负=净负债） |
| **净现金比** | `净现金 / 归母净资产`（可为负） |
| 商誉占比 | `商誉 / 归母净资产` |
| 其他应收款占比 | `其他应收款 / 总资产` |
| 应收+存货占比 | `(应收 + 存货) / 总资产` |
| 成本挤压 | `累计成本同比 − 累计营收同比 ≥ 25 个百分点`（**注意用累计，不是单季**） |

**没有**：资产负债率、流动比率、速动比率、存货/应收周转率、货币资金÷有息负债这个指标化版本。

### 每股 / 规模
EPS、BPS、TTM 归母净利、TTM 扣非净利、总股本。**没有**每股经营现金流、每股未分配利润、流通股本。

## 1.4 估值锚 → 合理价格区间

4 个锚，每个都是一个 `[low, high]` **价格**区间：

| 锚 | 条件 | low | high |
| --- | --- | --- | --- |
| 自身 PE 分位 | `EPS>0` 且 PE 历史 ≥20 点 | `P30(PE) × EPS` | `P60(PE) × EPS` |
| 自身 PB 分位 | `BPS>0` 且 PB 历史 ≥20 点 | `P30(PB) × BPS` | `P60(PB) × BPS` |
| 同业 PE 中位 | `EPS>0` 且同业 PE 中位 > 0 | `中位 × EPS × 0.85` | `中位 × EPS × 1.15` |
| 同业 PB 中位 | `BPS>0` 且同业 PB 中位 > 0 | `中位 × BPS × 0.85` | `中位 × BPS × 1.15` |

**合并规则**：`used = 自身历史锚，若为空则用全部`；`合理低 = median(used的low)`，`合理高 = median(used的high)`。
**优先自身历史是有意的**——同业倍数会把结论带反。

交叉核对提示：
- 结果中枢与同业锚中枢偏离 **≥40%** → 「合理区间以自身历史为准，同业只作参考」
- `used > 1` 且各锚中枢极差/中位 **≥40%** → 「同口径各方法分歧较大，参考价值下降」

缺数据时的静默规则：`EPS≤0` → 「PE 类估值不适用，只保留 PB 与同业参考」；PE 历史不足 20 点 → 明说；`BPS≤0` → 「净资产为负，PB 估值不适用」。

## 1.5 五维评分（100 分）与评级

**五个维度各 20 分。缺输入时给中性分，不给 0**——避免「没数据」被评成「很差」。

| 维度 | 条件 → 分 |
| --- | --- |
| **1 利润含金量**（扣非占比） | `null→10`｜`≥0.95→20`｜`≥0.85→14`｜`≥0.70→8`｜else `0` |
| **2 现金质量**（含金量+收现比） | `任一null→8`｜`含金量≥1.0 且 收现比≥1.0→20`｜`含金量≥0.8→14`｜`≥0.5→8`｜else `0` |
| **3 资产安全**（净现金比） | `null→10`｜`≥0.20→20`｜`≥0→14`｜`≥-0.50→8`｜else `0` |
| **4 成长性**（近4季同比中位） | `任一序列空→10`｜`营收&净利都≥15→20`｜`都≥5→14`｜`都≥0→8`｜else `0` |
| **5 资产干净**（商誉比/其他应收比） | `无资产负债表或净资产≤0→10`｜`商誉<5% 且 其他应收<5%→20`｜`商誉<20% 且 <5%→14`｜`商誉<30%→8`｜else `0` |

> 维度 2 有个不显眼的口径：`收现比` **只影响 20 分那一档**，14/8/0 三档只看含金量。照此移植。

**评级**：`≥85 优秀`｜`≥70 良好`｜`≥55 中性`｜`≥40 偏弱`｜else `较差`

## 1.6 风险清单（18 条）

阈值带（`Bands`）是卡片文案与风险清单的**唯一真源**，`null` = 中性（不夸也不警）：
`GOOD | WATCH | ALERT` 三档。

| 指标 | GOOD | 中性 | WATCH | ALERT |
| --- | --- | --- | --- | --- |
| 扣非占比 | ≥0.95 | ≥0.85 | ≥0.70 | else |
| 利润含金量 | ≥1.0 | ≥0.8 | ≥0.5 | else |
| 收现比 | **（永不 GOOD）** | ≥1.0 | ≥0.85 | else |
| 净现金 | 净现金比≥0 → GOOD | — | 净负债 | 有息负债/净资产≥1 **且**净负债 |
| 商誉比 | — | <0.10 | ≥0.10 | ≥0.30 |
| 其他应收比 | — | <0.05 | ≥0.05 | ≥0.10 |
| ROE | ≥0.15 | ≥0.08 | ≥0 | else |

> **顺序敏感**：`净现金 ≥0 → GOOD` **先判**，所以「净现金为正但有息负债 > 净资产」的公司是 GOOD，永远不会进 ALERT。照此移植。

其余风险项：
- 存贷双高：`货币资金/总资产 ≥20% 且 有息负债/总资产 ≥20%` → ALERT（要核实资金真实性）
- 应收+存货/总资产 ≥50% → WATCH（资产偏重）
- 成本挤压：累计成本增速 − 累计营收增速 ≥25pp → WATCH
- **单一产品依赖**：最大**产品**线（只看 `type==2`，行业/地区不算）收入占比 `≥90% 且 <99.5%` → WATCH
  （`≥99.5%` 不报——那通常只是「只披露了一个分部」）
- 某产品线毛利率为负且收入占比 ≥10% → WATCH（在拖累整体利润）
- 治理条目里所有 `ALERT` 级 → 转入风险清单

**明确不做风险项**（尽管类文档里提到过这些愿景）：连年亏损、审计意见非标（只经公告关键词）、股权质押比例高（只经关键词）、分红连续性。

## 1.7 治理 —— 只是公告标题关键词扫描

**重要**：没有实控人识别、没有量化质押比例、没有结构化审计意见字段、没有股东/解禁/机构持仓数据。这个模块的定位是「**去读那篇公告**」，不是结论。

- 窗口 **180 天**，最多 **6** 条；按 `referenceDate`（今天或最后估值日）算天数
- **一条公告只归一类**，优先级 **ALERT → GOOD → WATCH**（`解除质押` 含 `质押`，但因 GOOD 先判而归为「质押解除」；`会计差错更正` 同时命中 ALERT 的 `会计差错` 与 WATCH 的 `更正` → 归 ALERT）
- 按 `reason` 分组，每组只留**最新一条** + `count`（一次重组能发十几份公告）
- 排序：严重度（ALERT→WATCH→GOOD）→ 日期倒序

**关键词表**（`关键词 → reason`）：
- **ALERT（14）**：`立案→被立案调查`、`处罚→行政处罚`、`违规→违规事项`、`冻结→股份被冻结`、`终止上市→终止上市`、`退市→退市相关`、`无法表示意见→审计意见异常`、`否定意见→审计意见异常`、`保留意见→审计意见非标`、`监管措施→被采取监管措施`、`公开谴责→公开谴责`、`警示函→监管警示函`、`纪律处分→纪律处分`、`会计差错→会计差错更正`
- **GOOD（7）**：`解除质押→质押解除`、`回购→股份回购`、`增持→股东增持`、`分红→分红`、`权益分派→权益分派`、`股权激励→股权激励`、`预增→业绩预增`
- **WATCH（14）**：`质押→股东质押`、`减持→股东减持`、`问询→交易所问询`、`关注函→交易所关注函`、`诉讼→涉及诉讼`、`仲裁→涉及仲裁`、`减值→计提减值`、`商誉→商誉事项`、`重组→重大资产重组`、`风险提示→风险提示`、`更正→公告更正`、`解禁→限售股解禁`、`变更会计师→更换年审会计师`、`延期回复→延期回复问询`

报告里要带上**公告覆盖率**（扫描了多少条、最早/最新日期），因为实际窗口可能不足 180 天。

分页停止条件：已覆盖 ≥180 天，或该页不满，或到 4 页。结果按 `(date, title)` 去重后日期倒序。

## 1.8 移植陷阱（注释与代码不符，**照代码**）

1. **估值序列的负 PE/PB**：注释说负值转 null，**代码其实保留负值**（只 `isNaN` 判断），只在分位数阶段 `filter(>0)`。照代码移植。
2. **评分维度 2**：`cashToRevenue` 只区分 20 分档（见 1.5）。
3. **`Bands.netCash` 顺序**：净现金 ≥0 先判 GOOD（见 1.6）。
4. **跨年不做单季差分**（见 1.2 第 1 条）。
5. **成本挤压用累计同比，评分成长性用单季同比**——两条路径口径不同。
6. 取了但**从未使用**的字段：`f127`(行业)、`capex`、`totalLiabilities`、`minorityEquity`。可不移植，或移植了也不进指标。
7. **零缓存**：Android 每次点开都打 8–12 个请求，没有任何 Store/TTL/时间戳。**建议 A 项目补上**（见 1.9）。
8. `latestValuationDate` 是唯一没套 retry 的调用 → 移植时补。
9. 同业只取第 1 页 500 条：**排名与中位数都是页内口径**，`total`（板块成员数）可能更大。
10. 公告标题是 `contains` 模糊匹配，故意不精确——「重大事项公告」会漏。不要「改进」成更激进的匹配。

## 1.9 A 项目落地（含对 Android 的两处改进）

### 报告
沿用 A 项目 house style（见 `_technical_analysis.txt`：`一、二、三…` + 每段「含义：」+ 免责声明），落盘 `_fundamentals.txt`，`open -a TextEdit` 打开——与其它报告同一套路。

建议章节顺序（实现时**标题用词对齐 `FundamentalsReport.kt`**，此处为结构）：

```
一、综合结论            评级+总分+一句话判断
二、估值水平            PE/PB + 历史分位 + 同业中位/排名 + 合理价格区间
三、盈利质量            毛利率/净利率/ROE + 扣非占比 + 含金量 + 收现比
四、成长性              近 8 个单季表（营收/净利/毛利率/同比）+ 趋势判断
五、资产与负债          净现金比 + 商誉/其他应收/应收存货占比 + 有息负债
六、主营构成            产品线收入占比与毛利率（单一依赖提示）
七、治理与公告          180 天关键词扫描结果 + 覆盖率
八、风险清单            按 ALERT → WATCH → GOOD

```
