# 买点事件账本与模拟复盘

## 目的与入口

把观察池已经确认的买点保存为独立事件，回答“提醒后价格怎样变化”“按固定规则做一笔模拟交易会怎样”。复盘结果不反馈到选股评分、不改变买点门槛、不产生额外交易提醒、不修改实际持仓。

入口：**选股 → 📒 查看买点复盘报告**。

- **📒 查看买点复盘报告**：打开已经生成的本地文本报告。
- **🔄 后台更新买点复盘**：发起一次独立后台更新，菜单操作本身不请求行情。
- **⏸ 暂停买点复盘（选股提醒继续）／▶ 恢复买点复盘**：暂停或恢复事件采集与复盘，设置跨重启保留。暂停期间的买点不事后补造证据。
- 状态行显示是否开启、待落盘数量、最近复盘时间、队列未接收数量及异常。

模块默认开启，启动后仅记录新产生的合格买点，不把旧观察池的最近一次提醒反向补成完整样本。

## 事件与证据

`observation-pullback-v1` 表示当前观察池回踩企稳规则。满足规则且通过发通知前的观察池状态复核后，先投递事件，再按原逻辑发送系统通知。通知失败也保留事件，重试成功只补充通知结果。

唯一键由 **策略版本＋股票代码＋观察轮次首日＋信号日期** 组成；同股同轮次同一天只有一个事件，保留第一次满足条件时的证据，通知重试不覆盖触发价、不重复模拟买入。该粒度与现有同股每日提醒一次的规则一致。

证据包括：

- 股票、名称、选股来源组合、观察轮次、观察天数、触发时间与价格。
- 同时刻上证指数价格、指数 MA20 和报价时间。
- 个股 MA20、折算量比、昨收与历史日线日期、失效参考价。
- 资金来源、资金时间、净流入，以及每次连续确认的价格和资金样本。
- 通知正文、规则版本、最少确认次数与时长。
- 每事件冻结的模拟参数。以后修改默认值不会修改已有事件的参数。

已经退出、淘汰或到期的观察对象继续复盘；所有入账事件保留。首次取得的完整日线保存在账本中；同日期日线随后发生变更时停止更新该事件并显示待核对，不悄悄改写历史。复盘结果变化时追加快照，无变化的重复复盘不增加重复记录。

## 走势复盘口径

1. 触发日记为第 0 日。使用真实上证指数完整日线日期确定后续第 **1／3／5／10** 个市场交易日，不按自然日推算。
2. 个股在对应日期缺失、停牌或成交量为零时，该日结果留缺，不把下一个有报价的日期顺延冒充该日。
3. 缺少触发日指数日线，或已知有个股交易但指数日期缺失时，标记数据待补，不计算有歧义的后续序号。
4. 每个观察窗口展示：个股收盘相对触发价收益、指数收盘相对触发同时刻指数价格的收益、二者差值（百分点）。
5. 最大上涨／下跌仅使用触发次日起前 10 个市场交易日的有效个股日线高低价。触发当日的高低价可能发生在提醒之前，故不纳入；数据不完整时明确展示有效日线数量。
6. 当前未收盘日、未来日期不进入复盘，报告明确显示数据截至日期。它是盘后／历史观察结果，不是实时收益。
7. 检测到相邻有效日开盘与前收偏离超过 25% 时，异常日及之后的窗口标记为“价格口径待核对”，不计入有效收益或极值统计。异常前的有效窗口保留；该检查不能识别全部公司行动。

报告按策略版本与选股来源组合分组；一只同时来自严格、宽松的事件进入“严格+宽松”一组，不在总数中重复计数。每个窗口展示有效样本数／全部样本数，未到期或缺数据不当作零收益。相关事件可以重叠发生，统计只能用作样本观察，不能假装是共享资金组合回测。

## 固定模拟规则 daily-paper-v1

每个事件是独立的假设资金单元，**不扣实际现金、不改 `portfolio.json`、不调用真实下单接口**。

| 参数 | 默认值及用途 |
|---|---|
| 初始资金 | 每事件 10,000 元，保证不同信号有统一比较基数 |
| 买入数量 | 按 100 股一手向下取整，现金需覆盖股款和费用 |
| 入场时点 | 触发后下一个市场交易日开盘，仅尝试该日；不把触发价视为成交价 |
| 入场偏离 | 开盘与触发价偏离绝对值不超过 3%，避免以远离原信号的价格假设成交 |
| 滑点 | 买入加 0.1%、卖出减 0.1%，按 0.01 元向不利方向取整 |
| 佣金假设 | 每边成交额的 0.025%，最低 5 元 |
| 卖出税费假设 | 卖出成交额的 0.05% |
| 过户费假设 | 每边成交额的 0.001% |
| 退出限制 | 买入当日不卖出（模拟 T+1） |
| 止损 | 冻结触发时的失效参考价 |
| 止盈 | 模拟买入价＋2×（模拟买入价－失效参考价） |
| 最长观察退出点 | 触发后的第 10 个市场交易日收盘 |

这些值是本项目的模拟假设，不代表实际券商收费或全部证券的交易规则。事件里保留原参数；当前菜单只开放模块启停，不支持在途中改变一笔模拟交易的参数。

成交处理：

- 下个交易日缺失／零成交量时保留“数据待补”，不自动改为更晚一天入场。
- 开盘已经低于失效价、偏离超过限制、一字日、开盘不在日线高低价之间、加滑点后越过当日最高价、资金不足时不假设买入。
- 卖出时若同日触及止损与止盈，按止损优先；跳空跌破止损按开盘加不利滑点计算，不假设能按旧止损价成交。
- 买入当天收盘已跌破止损，则从下一日开盘尝试退出。
- 一字日或含滑点的卖价不在当日区间内，保留待退出，之后有效日线开盘再尝试，不伪造当日成交。
- 持仓中间有缺失／零成交量日线，停止推断后续退出，标为待核对；相邻日开盘与前收偏离超过 25% 时也暂停推断，提示核对价格连续性。该检查不能识别全部分红送转情形。

**所有成交标为“日线假设成交”。** 日线高低价用于事后可成交性筛查，无法验证开盘时盘口、涨跌停排队、成交顺序及真实成交量；这不是逐笔撮合，也不是可以直接执行的实盘回测。实际需要逐笔或分钟数据的验证属于后续阶段。

报告将触发价后的走势与模拟账户收益分开展示。模拟流水包括日期、方向、股数、价格、费用和退出原因，现金与持股数量独立维护。已平仓净盈亏扣除双边费用，收益率以该事件初始资金为分母；多事件收益不加总为账户收益。

## 后台与故障隔离

- 通知线程只做小型证据快照及 `put_nowait` 入队，不建立 SQLite 连接、不访问复盘行情、不等待复盘锁。
- 独立线程负责账本、日线与报告。主流程通过异常屏障调用；可选模块导入失败、初始化失败、磁盘写入失败、队列满都不改变原通知发送与回执逻辑。
- 自动抓日线在工作日 09:00 前或 15:20 起进行，90 分钟一个周期；手动更新可在盘中执行，但仍只使用完整日线。
- 每批最多复核 8 个事件，指数只取一次，同股票复用该批数据；尚有到期未处理事件时隔一分钟继续，按最早尝试时间排序。每个已尝试事件自动复核至少间隔 90 分钟，避免未到期事件反复占用请求。每个日线请求复用现有 10 秒超时。
- 盘中自动任务只落事件、更新本地报告，不自动请求额外复盘日线。
- 队列最多 256 项；数据库暂时不可写时保留当前消息并后台重试，后续消息在队列等候。队列满显示未接收数量，通知照常发送；程序突然结束可能丢失尚未落盘的内存消息。已提交数据可跨重启恢复。
- 暂停后不再接收新事件或发起后续请求；已发出的网络请求可能完成，已接收但未处理的队列消息在恢复后处理。暂停不停止原观察池和买点提醒。

本地文件：

- `entry_review.sqlite3`：事件、通知回执、日线证据和复盘快照；运行时可能同时有 `-wal`、`-shm` 文件。
- `_entry_review.txt`：自动生成的报告，明细最多展示最近 200 个事件，统计覆盖完整账本。
- `entry_review_config.json`：仅保存 `enabled` 开关。配置损坏时暂停附加模块并提示，不影响监控启动。

实现：`entry_review.py`（计算）、`entry_review_store.py`（持久化／报告）、`entry_review_service.py`（后台服务）。没有安装或运行外部 skill 包，只吸收其账本、费用和证据保留的设计思路。
