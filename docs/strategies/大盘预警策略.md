# 大盘预警策略 · 详细说明

> 对应代码：`market_alert.py`（预警引擎）+ `stock_menubar.py`（采集调度 `_check_market_alerts`、通知与打断）
> 对应 Android 版：`alert/MarketAlertEngine`（概念一致，参数与去重细节见文末差异）
> 用例：`tests/test_market_alert_realert.py`、`tests/test_notify_urgency.py`

---

## 一、策略思想

大盘预警的重点**不是尽可能多地发通知**，而是：

1. **真正危险时喊得响**（暴跌加深要持续喊，不能喊一次就闭嘴）
2. **不危险时不打扰**（确认轮次、跃迁去重、冷却、合并）
3. **一条通知说清楚**（同轮多维度命中只发一条汇总，标题跌幅与严重级别同口径）

预警语义刻意区分「风险提示」与「买卖建议」：反弹叫「弱势反抽观察」，
不暗示买入；下跌提示的是「关注仓位和止损」，不是抄底机会。

## 二、监控对象与节奏

| 项 | 设计 | 说明 |
|---|---|---|
| 监控指数 | 上证 `sh000001`、深证 `sz399001`、创业板 `sz399006` | 三个主要指数 |
| 检测频率 | **每 15 秒**一轮（`_check_market_alerts`） | 轻量判定，不重算指标 |
| 交易时段 | 9:30–11:30、13:00–15:00（含 15:00 整分） | 其余时间不检测 |
| 跨日重置 | 新交易日自动 `reset_daily()` | 否则昨天触发过的级别今天不再报 |
| 数据来源 | 行情缓存 `stock_data`（成交额转亿） | 快照带时间戳进引擎校验 |

## 三、预警级别

| 级别 | 图标 | 标题 | 含义 | 打断强度 |
|---|---|---|---|---|
| `INFO` | 💡 | 弱势反抽观察 | 提示，不构成买入信号 | 普通通知 |
| `WARNING` | 📉 | 大盘转弱提醒 | 市场明显走弱 | 普通通知 |
| `DANGER` | 🚨 | 大盘风险预警 | 需要控制仓位 | **urgent**（时效性通知 + 置顶横幅） |
| `CRASH` | 🛑 | 大盘严重风险 | 系统性风险 | **urgent**（同上，且主线程 NSAlert 兜底） |

级别必须**跟着标题跌幅走**：合并通知若按全场最惨指数跌幅已达 CRASH 线，
标题/级别都要升到 CRASH——不能出现「大盘转弱提醒」配「-3.56%」。

## 四、五个检测维度

### 1. 绝对跌幅（`absolute`，主信号）

| 级别 | 阈值（当日涨跌幅） | 确认要求 |
|---|---|---|
| WARNING 转弱 | ≤ **-0.8%** | **连续 2 轮**确认（`confirm_rounds=2`，约 30 秒） |
| DANGER 风险 | ≤ **-1.2%** | 单轮立即触发 |
| CRASH 严重风险 | ≤ **-2.5%** | 单轮立即触发 |

> 为什么 WARNING 要两轮：-0.8% 是最容易被日内噪声碰到的线，先确认再喊；
> DANGER/CRASH 本身罕见，宁可快也不能漏。

**继续下探再提醒（`continue`）**：某级别已提醒过、市场又继续跌，
每再跌 **-0.5%**（`realert_step`）就再喊一次「仍在创新低」，
文案带上「较上次提醒再跌 X%」。首次提醒报**状态**，续报报**恶化**。

### 2. 急跌速度（`speed`，5 分钟窗口）

| 级别 | 5 分钟内跌幅 |
|---|---|
| WARNING | ≤ -0.5% |
| DANGER | ≤ -0.8% |
| CRASH | ≤ -1.2% |

节流与例外：
- 每个指数**每分钟最多检测一次**
- 开盘后 5 分钟内（9:30–9:35）不检测（集合竞价后的正常波动）
- 午盘开盘后 5 分钟内（13:00–13:05）不检测（重新建立基线）
- 5 分钟窗口数据不足 **80%** 不判（间隔不完整不比速度）

### 3. 量能（`volume`，只做附加信息，不单独触发）

相对**同时段历史基线**（同 code、同「时:分」的历史成交额均值）：

| 倍数 | 标签 |
|---|---|
| ≥ 1.5 | 放量 |
| ≥ 2.0 | 巨量 |
| ≥ 3.0 | 天量 |

命中时**附加**到当轮已有预警正文（`📊 巨量下跌（2.3倍）`），没有其他预警则不发。
基线少于 **5 个**历史点不判。用同时段基线而非全天均值，避免「开盘量天然大」被误判成放量。

### 4. 弱势反抽观察（`recovery`，INFO 级）

| 条件 | 阈值 | 为什么 |
|---|---|---|
| 此前跌幅 | 当日涨跌幅 ≤ -0.8% | 没跌过就不叫反抽 |
| 自日内低点反弹 | ≥ +0.5% | 确实弹起来了 |
| 频次 | **每日一次**（按日期键去重） | 反复横跳不刷屏 |

文案固定提醒「这可能只是下跌中继，不构成买入信号」——**刻意不写买入语义**。

### 5. 多指数共振（`correlation`，每日一次）

满足任一即触发：

| 条件 | 内容 |
|---|---|
| 条件一 | ≥ 2 个指数跌幅 ≤ -0.8% **且** 三指平均跌幅 ≤ -0.7% |
| 条件二 | 三个指数全跌 **且** 至少一个跌幅 ≤ -1.2% |

级别：平均跌幅 ≤ -1.5% 时 DANGER，否则 WARNING。

## 五、防刷与去重（状态机）

### 重新武装（rearm）

指数涨跌幅回到 **≥ -0.6%**（`rearm_threshold`）时，清空该指数的
已触发级别 / 确认计数 / 待确认级别 / 上次提醒跌幅——**恢复预警能力**，
后续再跌可以重新报各级别。

> ⚠️ 历史坑（2026-10-08 修复）：旧实现把「清空已触发」写在 `if not state.armed` 里，
> 而 `armed` 初始为 True 且**全代码从未置 False** → 清空永远不执行 →
> 同级别预警全天只报一次，创业板砸到 -3.93% 全程静默。
> 现条件为 `if state.level_triggered or not state.armed`。回归见
> `tests/test_market_alert_realert.py`。

### 合并通知（flush_alerts）

同一轮（15 秒）里可能同时命中绝对跌幅 + 速度 + 量能 + 共振，
只发**一条**汇总通知：取最高级别、标题跌幅取**全场最惨指数**、正文列全部指数涨跌幅。

### 数据校验（异常快照直接丢弃）

| 校验 | 规则 |
|---|---|
| 价格 | ≤ 0 丢弃 |
| 时间戳超前 | 超过当前时间 +5 分钟丢弃 |
| 时间戳倒退 | 比上一条更早丢弃 |
| 单 tick 跳变 | 相邻价格跳变 > 5% 丢弃（疑似脏数据） |

## 六、通知与打断语义

| 级别 | 通道 |
|---|---|
| `danger` / `crash` | 置顶告警横幅（主通道，与通知授权/专注模式解耦）→ `afplay` 音效 + Dock 弹跳 → CRASH 级主线程 `NSAlert` 兜底 |
| `warning` / `info` | 系统通知（`Active` 级） |

- 横幅冷却：级别上升立即弹，同级 **180 秒**节流（避免 3 指数合并抬级时每 15 秒弹一次）
- **「发送成功」≠「用户看到」**：通知 XPC 超时按失败处理并走兜底通道
- 详见 `CHANGES_2026-10-08.md`（macOS 通知 `timeSensitiveSetting` 坑）

## 七、边界行为（回归测试覆盖）

1. **同级别已触发后继续大跌** → 每再跌 0.5% 发 `continue` 续报，不再全程静默
2. **小幅反弹不误报 realert**：-2.5% → -2.3% 不到 0.5% 步长，不触发续报
3. **rearm 后可以重新报**：涨回 -0.6% 以上清状态，再跌重新走确认流程
4. **标题跌幅取全场最惨**：创业板 -3.76% 时标题写 -3.76% 而不是触发指数的 -1.21%
5. **级别跟标题跌幅对齐**：标题跌幅已达 CRASH 线则级别升到 CRASH
6. **跨日自动重置**：昨天触发过的级别今天可再报（`reset_daily` 已挂到跨日检测）

## 八、参数总表

| 参数 | 值 | 用途 |
|---|---|---|
| absolute WARNING / DANGER / CRASH | -0.8% / -1.2% / -2.5% | 绝对跌幅分级 |
| confirm_rounds | 2 | WARNING 确认轮数（DANGER/CRASH 单轮） |
| speed WARNING / DANGER / CRASH | -0.5% / -0.8% / -1.2% | 5 分钟窗口速度分级 |
| speed_window | 300 秒 | 速度窗口 |
| speed_check_interval | 60 秒 | 速度检测节流 |
| volume 1.5 / 2.0 / 3.0 | 放量 / 巨量 / 天量 | 相对同时段基线 |
| recovery_threshold | +0.5% | 自日内低点反弹幅度 |
| recovery_min_drop | -0.8% | 反抽前需有的跌幅 |
| correlation 条件一 | 2 个 ≤-0.8% 且均值 ≤-0.7% | 共振判定 |
| correlation 条件二 | 全跌且其一 ≤-1.2% | 共振判定 |
| rearm_threshold | -0.6% | 重新武装线 |
| realert_step | -0.5% | 继续下探续报步长 |
| 横幅冷却 | 180 秒 | 同级节流 |

## 九、与 Android 版的差异

| 项 | Android | macOS |
|---|---|---|
| 继续下探续报 | 无（同级别只报一次） | `realert_step=-0.5%` 持续报恶化 |
| 标题跌幅口径 | 触发那条的单指数 | 全场最惨指数，级别随之对齐 |
| 打断层级 | 系统通知 | 置顶横幅 + 音效 + Dock + NSAlert 三层 |
| 其余规则 | —— | 阈值、确认轮次、rearm、合并、量能基线一致 |

## 十、使用与限制

- 入口：菜单栏自动检测（无需手动开启，`market_alert_enabled=True`）。
- **阈值参照物是上证标尺**（-0.8% / -1.2% / -2.5%），对创业板/科创板这类高波动指数偏保守；
  是否改为按**持仓加权跌幅**定阈值待定（见 `CHANGES_2026-10-08.md` 遗留项 1）。
- 量能基线需积累同时段历史点，开盘初期基本不参与判定。
- 本策略输出均为风险提示，不构成投资建议。
